# Инструкции для работы над Voxhold Native Rust

Этот репозиторий — незавершённый перенос Windows-клиента на Rust и GPUI. Перед изменениями изучите [архитектуру](docs/architecture.md), [статус](docs/status.md) и фактический код. Не объявляйте паритет или готовность к выпуску без проверки каждого сценария.

Сетевые контракты сверяйте с обработчиками backend и поведением frontend, а не только с OpenAPI. Контрольные ревизии на момент переноса: backend `9b29fdd6d5dc818b7408e4892b8e68b27d123831`, frontend `ed7cb00ae12398753a8ef48a5a33b864e20cb04c`. При новой проверке указывайте использованные ревизии. Не изменяйте исходные репозитории в рамках этого проекта.

Сохраняйте разделение UI, API и медиа. Запросы не должны блокировать поток UI; отменяйте или игнорируйте устаревшие ответы при переходах. Не добавляйте элементы без действующего сценария. Для удалённых серверов обязателен HTTPS; HTTP допускается только для localhost и loopback. Не отправляйте токены на другой origin, не записывайте секреты и содержимое личных сообщений в логи.

При изменениях запускайте подходящие проверки и отдельно сообщайте результат сборки, тестов, ручного запуска и проверки на настоящем сервере. Если пользователь просит не запускать их, соблюдайте это и явно указывайте, что проверка не выполнена. Не утверждайте выигрыш производительности без измерений. Учитывайте, что опциональный `libwebrtc` содержит статически слинкованный C++.

## Ветки и план развития

План работы с критериями UI 1:1 относительно Go, зависимостями, сетевыми контрактами и журналом выполнения — [docs/development-plan.md](docs/development-plan.md). Для новой задачи выполни `git fetch origin`, возьми актуальный `origin/dev` и создай `codex/<задача>`. После проверок запушь ветку и открой PR в `dev`. Порядок этапов и разбиение PR для пакета W описаны в [docs/w-workflow.md](docs/w-workflow.md). Проверки реализации идут по этапам, итоговая приёмка `R08` выполняется в `W13`. `main` получает выпуск через отдельный PR из `dev`. После merge обнови журнал плана и ссылку на коммит.

## Ограничение размера файлов

Целевой максимум для рукописного файла — 1000 физических строк, включая пустые строки и комментарии. Если дальнейшее разбиение ухудшит связность кода, допустимо исключение до 1200 строк включительно. Путь и конкретную причину исключения записывай в версионируемый [список исключений](scripts/file-size-exceptions.txt) рядом с проверкой. Свыше 1200 строк файл нужно разделить.

Правило действует для исходников, тестов, скриптов, workflow и документации. Сгенерированные и сторонние файлы, lock-файлы, бинарные ресурсы и `assets/` исключаются по явным путям и шаблонам в `scripts/check-file-sizes.ps1`. Pre-commit проверяет содержимое индекса Git, CI — все отслеживаемые файлы. Подключение хука: `git config --local core.hooksPath .githooks`.
