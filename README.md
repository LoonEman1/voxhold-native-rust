# Voxhold Native Rust

Экспериментальный Windows-клиент Voxhold на Rust и GPUI. Перенос не завершён: это не готовая замена прежнему клиенту.

В основном интерфейсе подключены вход, серверы, каналы, текстовая история с ручной загрузкой страниц и виртуализированным списком, обновления в реальном времени, поиск, закрепления, действия сообщений, вложения каналов, отметки прочтения видимых сообщений, недавние диалоги, личные и административные настройки, голос и просмотр видео. Это описание имеющегося кода, а не подтверждение исправности или паритета: release-сборка и старт окна проверены, но сценарии на сервере и визуальный паритет не проверены. Вложения в личных диалогах, полный набор настроек, видеосценарии, системные уведомления и визуальное соответствие текущему Go-клиенту ещё требуют работы. Подробности — в [статусе](docs/status.md). Порядок разработки, GitHub workflow и критерии интерфейса 1:1 описаны в [плане переноса](docs/development-plan.md).

Готовый Windows x64 EXE после локальной сборки: `bin/Voxhold-native-rust.exe`. Отдельная DLL медиадвижка не требуется.

## Сборка по необходимости

Для Windows x64 нужны актуальный Rust MSVC toolchain, Visual Studio C++ Build Tools и Windows SDK. В PowerShell из каталога проекта:

```powershell
cargo run -p voxhold-native-rust
cargo test -p voxhold-api
```

При первом запуске Cargo загружает зависимости. Медиакрейт включён по умолчанию и использует `libwebrtc`, содержащий статически слинкованную библиотеку WebRTC на C++.

Перед коммитом включите общий хук проверки размеров файлов и пробелов:

```powershell
git config --local core.hooksPath .githooks
```

Тот же скрипт `scripts/check-file-sizes.ps1` запускается в Windows CI по всем отслеживаемым файлам; исключения и обоснования ведутся в `scripts/file-size-exceptions.txt`.

В GitHub Actions workflow **Windows** проверяет ограничения размера файлов при каждом запуске. Если изменены только `README.md`, `AGENTS.md` или Markdown-файлы в `docs/`, Rust-тесты и упаковка пропускаются. Для остальных изменений workflow проверяет форматирование и запускает тесты всего workspace с включённым медиа. После успешных тестов на `dev` и `main` он публикует артефакт `voxhold-windows` с release EXE и каталогом `assets/`. Когда этот workflow попадёт в `main`, полный прогон и сборку архива для другой ветки можно запустить через **Actions → Windows → Run workflow**.

Клиент требует HTTPS, кроме localhost и loopback. Токен сессии хранится в памяти; не записывайте его и пароли в журналы или тестовые данные. Производительность относительно прежнего клиента не измерялась. См. [архитектуру](docs/architecture.md).

### Локальный кеш Cargo

Для сборок на Windows создайте `.cargo/local.toml` в основной копии проекта. Файл игнорируется Git, а worktree внутри основной копии наследуют его через настройки Cargo. Для отдельного worktree с поддержкой `local.toml` укажите в нём тот же путь. Выберите короткий каталог вне OneDrive, доступный на запись.

```toml
[build]
target-dir = "C:/vxt"
incremental = false

[profile.dev]
debug = 0

[profile.test]
debug = 0
```

Единый путь позволяет повторно использовать совпадающие артефакты зависимостей между worktree. Rust отключает инкрементальную компиляцию и отладочную информацию для локальных dev/test-сборок, поэтому изменённые крейты могут пересобираться дольше, а пошаговая отладка потребует вернуть символы. Для обычной проверки компиляции используйте `cargo check --workspace --locked`. Для тестов Cargo использует тот же каталог. Фактический путь из каждого worktree можно проверить в PowerShell.

```powershell
(cargo metadata --locked --no-deps --format-version 1 | ConvertFrom-Json).target_directory
```

Если Cargo показывает другой путь, проверьте `CARGO_TARGET_DIR`, `CARGO_BUILD_TARGET_DIR` и параметры команды. Выпускные сборки и разные наборы features могут создавать дополнительные артефакты и в общем каталоге.

Если вложенный worktree повторяет те же `rustflags`, запускайте проверку из основной копии с `--manifest-path target/<worktree>/Cargo.toml`. Cargo возьмёт флаги из основной копии один раз, и зависимости смогут использовать тот же кеш.
