# Состояние переноса

Исходная база — локальное дерево `wgpu-desktop-parity` с незакоммиченными изменениями голоса и видео. Наблюдавшиеся ревизии: backend `9b29fdd6d5dc818b7408e4892b8e68b27d123831`, frontend `ed7cb00ae12398753a8ef48a5a33b864e20cb04c`. Полная совместимость с ними не проверена.

В исходном коде основного интерфейса подключены вход, выбор сервера и канала, участники, текстовая история с ручной загрузкой страниц и виртуализированным списком, обновления в реальном времени, поиск и закрепления, действия сообщения и обсуждения, вложения каналов, отметки прочтения видимых сообщений, недавние диалоги, личные настройки, настройки канала и сервера. Административные панели включают название, CORS, баны, экспорт диагностики и применимые к типу канала параметры. Имеются панели голоса и просмотра видео с ограниченными переключением и восстановлением; медиакрейт включён по умолчанию. Для вложений каналов подключены выбор файлов, черновики, загрузка и сохранение; передача буферизуется в памяти. Наличие элемента или метода не подтверждает работу соответствующего сценария на сервере.

До паритета остаются, среди прочего: проверка и завершение личных сообщений, настроек и администрирования, включая роли и квоты; вложения личных диалогов, аватары и предпросмотр; системные уведомления и тема; устойчивое переподключение; завершение голосовых и видеосценариев, выбора устройств и трансляций. Визуальное соответствие веб-клиенту, ассеты, адаптивность и доступность также требуют работы. Необходимо проверить права, E2EE, новостные каналы и личные диалоги с сервером. Измерений производительности нет.

Проверено на Windows x64: `cargo build --release --locked -p voxhold-native-rust` с включённым медиа завершился успешно; `cargo check --locked -p voxhold-native-rust` успешен; тесты API 4/4 и media 6/6 успешны. Проверка запуска обнаружила отзывчивое окно приложения; пользовательские сценарии и работа с реальным backend не проверены. Выполняемый файл использует системные Windows DLL, отдельная DLL медиадвижка не нужна. Ресурсы и иконки компонентов требуют визуальной проверки. API запрещает удалённый HTTP и HTTP-перенаправления с токеном. Медиазависимость по умолчанию включает статически слинкованный C++ `libwebrtc`.

## Исправления по ревью PR #2–#4 (14 ноября 2026)

Ветка `codex/r01-r02-review-fixes` от `dev` `6213379`, замечания из
[review-r00-r02.md](review-r00-r02.md).

- Автодогрузка больше не читает `ListState` из обработчика колеса: проверка
  отложена в фоновую задачу, диапазон и канал сверяются заново. Закрывает
  падение `RefCell already mutably borrowed`.
- `channels.changed`, `channel.*`, `server.member_*` и `server.deleted`
  инвалидируют `access_generation`, очищают подтверждённую историю и панели,
  перечитывают список каналов; `403/404` в истории делают то же.
- Слияние сообщений хранит отдельно версию тела и реакций: `message.updated`
  без `reactions` не сбрасывает реакции. Поздний ответ POST (текст и файл) не
  возвращает удалённый id и применяется только в своём scope.
- При reconnect окно истории заменяется непрерывным снимком: старые строки
  ниже страницы больше не создают дыру, удалённые на сервере строки исчезают.
- Диапазон видимых строк учитывает `item_ix == item_count` в конце истории и
  расширяется назад; read отправляется после кадра, а не по устаревшему
  `visible_range` колеса.
- Якорь снимается в момент применения страницы; `events_version` заменён на
  `history_version` (только сообщения), добавлен backoff 20/8/3 с для
  `429`/`5xx`/прочих ошибок и подпись повтора.
- Выход обрывает WS-задачу, закрывает голос, поднимает поколения, очищает
  вложения, настройки и панели; поздние ответы старой сессии отбрасываются.
- После входа выбирается первый сервер; в узком окне в списке каналов есть
  полоса серверов.
- Поля входа имеют одну подложку; тема `gpui-component` синхронизируется при
  старте, переключении и смене системной темы.
- Подписи карточки входа вынесены в общие координаты, добавлена кнопка
  «Назад» к адресу.
- Иконки каналов, рейла, шапки, темы и отправки подключены из `assets/icons`
  через `AssetSource`; `README`-комплект ищется рядом с EXE.
- Правая панель загружает аватары по `Client::avatar` с ключом
  `(user_id, avatar_version)` и обновляется по `avatar.updated`.
- `windows.yml` теперь запускает `cargo check --workspace --locked` и
  `cargo test --workspace --locked` (приложение, API и медиа).

Проверено локально: `cargo fmt --all -- --check`, `cargo test -p voxhold-native-rust`

### Повторное ревью PR #8

- Ответ `message/context` применяется тем же слиянием, что история и WS:
  `deleted_ids` побеждает снимок, версии тела и реакций сверяются раздельно,
  `pending_edits`/`pending_reactions` переносятся на контекстные строки. Если
  цель перехода удалена за время запроса, окно остаётся прежним, а в ошибке
  показано «Сообщение недоступно».
- Замена окна сбрасывает `older_request`, `loading_older`, ошибку и задержку
  повтора старой страницы. Поздний ответ старого курсора игнорируется, даже
  если уже началась догрузка нового окна.
- `MessageTools` применяет подтверждённый `ReactionsUpdate` к выбранному
  сообщению и подсветке пикера; повторный клик берёт `me` из нового состояния
  (PUT → DELETE). Ответы с прежней ревизией или чужим `message_id`
  отбрасываются, ошибка не меняет последнее подтверждённое состояние. Лента и
  WS синхронизируют открытую панель через `sync_message`.
- Успех реакции больше не увеличивает `revision` панели, поэтому не запускает
  загрузку последних 50 сообщений. `ReactionsUpdate` применяется к строке через
  общий обработчик, даже если выбранное сообщение старше окна; выбор и пикер
  сохраняются.
- «К последним» инвалидирует ожидающий `/context` (`context_request` и
  `pending_jump`). Поздний ответ цитаты после загрузки последних сообщений
  отбрасывается и не возвращает старое окно.

Проверено: `cargo fmt --all -- --check`, `cargo test --workspace --locked`
(56 тестов приложения, 5 API, 6 media), release-сборка. Добавлены
регрессионные тесты на поздний `/context` с удалением/правкой/реакцией,
сброс старой догрузки, последовательность реакций в пикере, реакцию на строке
за пределами последних 50 и порядок ответов «К последним» → `/context`.
